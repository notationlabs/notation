Runtime and infra modules import each other through import attributes, and runtime modules declare their functions with `lambda()` (RFC 0008).

- A runtime module imports infra `with { type: "infra" }`, and infra imports a runtime module `with { type: "runtime" }`. Importing a file that matches the `runtimeModules` globs without the attribute fails, as do `type: "infra"` in infra and `type: "runtime"` in runtime code.
- A runtime module imports `lambda` from `@notation/aws/lambda` with `{ type: "infra" }` and calls it without `code`: `const { handle } = lambda({ id: "checkout", timeout: 5, grants: [orderQueue.grant(["SendMessage"])] })`. Each handler that `handle` makes, and the module exports, belongs to that function. The `resource` export and `LambdaResource` are removed; a module that exports `resource` fails with a migration message. `@notation/aws/lambda.fn` no longer exports `handle`.
- Runtime modules run after all of infra, as stripped copies that keep only the `lambda()` calls, the handlers they make and what those reference. `lambda()` settings can use any infra value, and the plan doesn't depend on the order infra modules load.
- `route()`, `queue.consume()` and `schedule()` wire a handler when evaluation ends. `consume()` returns nothing. A handler of the wrong kind fails at the infra call site, and a handler that isn't exported fails at plan.
- `compile` writes `notation-env.d.ts`, evaluates the infra phase, then bundles each function to `dist/functions/<id>/index.mjs`, with a dispatcher to its handlers.
- `notation types` writes `notation-env.d.ts` at the project root. It has one block per attributed import specifier, and catch-all blocks for `./*` and `../*` that give an import with no block an error type. `notation watch` writes it again when a source file is created, deleted, moved or changed. The file needs TypeScript 7.1. Exclude it from Prettier and typescript-eslint.
- `@notation/resource` exports the view types `RuntimeView`, `InfraView`, `Handler`, `RuntimeRef`, `InfraOnly`, `RuntimeOnly`, `Grant` and `FunctionDeclaration`, which `@notation/core/types` re-exports. It also adds the linking API: `createStandIn`, `linkRuntimeModules`, `createHandlerRef`, `declareRuntimeFunction` and `resolveRuntimeTarget`. The resource graph has `runtimeFunctions`.
- `handle.<kind>(fn)` returns a `LambdaHandler`: a function with a type-only mark. Infra sees it as a `LambdaRef`, a `RuntimeRef` whose `function` is a `LambdaFunction`, and can wire it but not call it. An exported `lambda()` result is seen by infra as a `LambdaFunction`. A `LambdaFunction` is a `LambdaGroup` without `handle`.
- `route()`, the router methods, `queue.consume()` and `schedule()` take a `LambdaRef` of the right event, or a Lambda group. A plain function, or a handler imported without the attribute, no longer type-checks.
- Runtime code reads infra values through a `type: "infra"` import of a local infra module. The function's bundle turns `orderQueue.url` into `read("infra/orders#orderQueue", ["url"])`, and a whole binding used as a value into a read of the whole binding. A binding that is data is delivered whole. Any other binding, such as a queue, delivers its own output values and primitives, such as `url`, `arn` and `id`, and not its `config`. `compile` lists the reads left after tree-shaking in `dist/functions/<id>/reads.json`, and plan and deploy deliver their values through the function's `Runtime` map, under output keys such as `infra/orders#orderQueue.url`. A read of an infra function, or of a value that isn't an output or data, fails at plan. So does a function whose environment variables are over Lambda's 4 KB limit, naming the function and its largest reads. A value not known at plan counts as empty, and deploy checks the limit again. Calling infra from runtime code, changing it, using a namespace import of it as a value, or importing an infra package without the attribute fails the build. `@notation/resource/outputs` exports `read`, `outputKey`, `parseOutputKey`, `setOutputValues` and `addOutputSource`.
- Runtime code sees a queue's `url` and `arn` as strings. It can call resource factories, such as `lambda()`, and `queue.grant()`, and no other infra function or method. A binding that isn't data keeps only its output values and primitives, such as a queue's `url`, `arn` and `id`, and its `grant` methods. It leaves out its `config` and its `resources`. A `LambdaGroup`'s `arn` is now a property that isn't enumerable, not a getter, so that a whole read delivers it. `lambda()` returns `{ handle }` to runtime code, and other factories return their result viewed as a binding. `RuntimeFactory` marks a factory with the signature that runtime code sees.
- `lambda()` takes an `id` that isn't a string literal, such as one read from infra, and checks it when it runs. A literal `id` is still checked by TypeScript.
- Infra can read values from a handler's function, or from an exported `lambda()` result, before the runtime modules are linked, such as `checkout.createOrder.function.arn`, `checkout.checkoutFn.arn` or `checkout.createOrder.function.grantInvoke()`, and pass them to resources, which resolve them after linking. Calls on the function, such as `policy.contribute(...)`, are made at linking. Reading the function's `id`, or turning a value read from it into a string, fails with the call site. A Lambda group has `arn` and `grantInvoke()`. `@notation/resource` exports `isDeferred` and `resolveDeferred`.
- `sqsBatch` and `dynamoDbBatch` handlers take the SQS or DynamoDB stream event and return the batch response.
- Tests import runtime modules without an attribute and call handlers directly. `setOutputs()` from `@notation/aws/testing` sets the values that runtime code reads from infra, keyed as `infra/orders#orderQueue.url`. The loader hook, `node --import @notation/aws/testing/register`, and the Vitest plugin, `notationTesting()` from `@notation/aws/testing/vitest`, serve each `type: "infra"` import from those values, and a provider's infra half, such as `@notation/aws/lambda`, as its runtime half. The hook also drops the attributes before Node resolves, so cycles of attributed `.ts` imports load.
