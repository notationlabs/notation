A schema item can declare `collect`, and any code can add to that param with `resource.contribute(values, { by })` while infra is being evaluated. Contributions are combined in an order sorted by content, and a conflict names both contributors. `mergeContributions` merges maps key by key. `contribute` also accepts a function and its `deps`, as `resource.contribute(({ deps }) => values, { by, deps })`. The receiving resource depends on the deps, and deploy runs the function with their real outputs. `resource.outputValue(key)` returns an `OutputValue` token that config and contributions can hold whole. Turning a token into a string throws an `OutputValueStringError`. The token makes its holder depend on the resource it came from, and deploy fills in the real value. `resource.dependOn(other)` adds a dependency after construction. Contributions close when evaluation ends, and `onEvaluationEnd` registers a callback that runs before the close. Plan marks a value that waits on an undeployed output unknown at its own path. At plan, `deriveParams` and function contributions receive views of their deps, and reading the output of a dep that has none yet throws `PendingOutput`. When `deriveParams` reads one or throws, plan marks every param it would set, and every param not set in config, unknown. When a function contribution reads one or throws, plan marks every collected param of its resource unknown. `BaseResource` gains `contribute`, `dependOn`, `getDependencies`, `planParams` and `outputValue`. `@notation/utils` adds `sortedJson`, JSON with sorted keys.
