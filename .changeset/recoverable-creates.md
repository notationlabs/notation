Deploy needs new IAM permissions: `iam:TagRole`, `events:TagResource`, `events:ListTagsForResource`, `sqs:TagQueue` and `sqs:ListQueueTags` for the create tokens, and `logs:DescribeLogGroups` for the log group's read.

A deploy can now recover a resource that an abandoned deploy created but did not record.

- Deploy writes a state record with `lastOperation: "creating"` before it calls a resource's `create`, and replaces it when the create is done. The record lists, in `creates`, the IDs of the executions whose creates may have made the resource. An execution's create token is `notation:create:<execution id>:<resource id>`, the same for each attempt, so a later deploy can compute it. Plan and deploy decide **create** for a resource with a `creating` record, and its dependents plan against unknown outputs.
- `@notation/resource` adds `ResourceAlreadyExistsError`. A `create` handler throws it when the provider refuses the create because the resource already exists.
- Deploy takes over or deletes an existing resource only with proof that one of Notation's own creates made it. A resource class says how the proof is made with the new `ownership` option. With `"token"`, `create` records the create token on the resource, and `find(params, token)` checks it. With `"parent"`, the resource lives inside something Notation owns, so any resource with the desired key is Notation's. Without `ownership`, deploy never takes a resource over. With the proof, deploy reads the resource, records it with the params that the read returned, and then updates, replaces or keeps it. Without it, deploy fails. It clears a `creating` record, and writes back a full record that a drift read reported gone. Drift-recreate follows the same rule.
- With `ownership: "token"` and a `creating` record, deploy calls `find` with the tokens of the earlier executions before it calls `create`, and takes over what it finds. A resource whose key the provider assigns, such as an API Gateway API, is then not made a second time.
- When the lookup of a create with an unknown outcome finds the resource, deploy records it with the params that its read returned, and puts what is missing, such as a rule's targets or a log group's retention, in the same deploy.
- After a takeover, deploy updates each param that the resource's `read` does not return, because it cannot tell whether the param matches config. A param whose difference would replace the resource is assumed to match.
- `LambdaLogGroup`'s update now sets each changed param with its own API call. Before, a change to `kmsKeyId` or `tags` was sent to `PutRetentionPolicy`. A deploy that changes them needs `logs:AssociateKmsKey` or `logs:DisassociateKmsKey`, and `logs:ListTagsForResource`, `logs:TagResource` and `logs:UntagResource`.
- The lookup of a create with an unknown outcome follows the rule too. `find` is used only with `ownership`, and the read by key only with `ownership: "parent"`. A resource class that defines `find` must set `ownership`, and `defineOperations` throws otherwise.
- When create fails with another error that is not classified as unknown, deploy clears the `creating` record, but only when the deploy started from no record.
- The orphan sweep and destroy delete the resource of a `creating` record only with the proof. With `"token"`, they call `find` with the tokens of the executions that the record lists, and delete what it finds. With `"parent"`, they delete by the key that `find` returns or the record holds. Otherwise they remove only the record, and emit a `skip` event with the reason `not-created`, `key-unknown` or `ownership-unproven`.
- When the `creating` record names another key than config, the resource that the abandoned create may have made under the old key is left in the provider.
- `notation plan` notes when deploy may take over an existing resource: for a create of a resource with `ownership: "parent"`, or with `ownership: "token"` and a record of an earlier create.
- `awsCreate` in `@notation/aws/resources` takes an `alreadyExists` option. `LambdaIamRole`, `LambdaFunction`, `LambdaPermission`, `LambdaLogGroup`, `eventBridge.EventBus`, `eventBridge.Rule`, `sqs.Queue`, and API Gateway's `Stage` and `Route` report an existing resource as `ResourceAlreadyExistsError`, as does Cloudflare's `WorkerScript`. `LambdaIamRole`, `eventBridge.EventBus` and `eventBridge.Rule` tag themselves with the create token and gain a `find`.
- `LambdaFunction`, `LambdaIamRole`, `eventBridge.EventBus`, `eventBridge.Rule`, `sqs.Queue`, `LambdaEventSourceMapping` and API Gateway's `Api` prove ownership by token. `LambdaPermission`, `LambdaLogGroup`, `LambdaFunctionConcurrency`, `LambdaRolePolicy`, `LambdaRolePolicyAttachment`, and API Gateway's `Route`, `Stage`, `LambdaIntegration` and `RouteAuth` prove it by their parent, as do `std` `File` and `Zip`, and Cloudflare's `WorkerSubdomain`. Cloudflare's `WorkerScript` records the create token as a Worker tag and proves it by token. Its update keeps the Worker's tags. `LambdaLogGroup` gains a `read` and a `find`, so deploy takes over the log group that Lambda makes when a function first logs, but not one made before the function was last modified, as one that a deleted function left, unless a `creating` record that an earlier execution left holds its name.
- `LambdaLogGroup` reports a failure to set its retention policy, after the log group was made, as `ResourceCreationUnknownError`. The EventBridge rule checks that no rule with its name exists before `PutRule`. After `PutRule` it checks the rule's create token, and refuses a rule without it. When its targets can't be put during create, it deletes the rule, and reports a failed delete as `ResourceCreationUnknownError`. `sqs.Queue` checks its create token after `CreateQueue`. `LambdaRolePolicyAttachment` treats a detached policy as deleted.
