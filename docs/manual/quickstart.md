# Quick Start

Build and deploy a todo API to AWS in under 5 minutes.

## 1. Create a project

```sh
npm create notation@alpha my-app
cd my-app
npm install
```

```sh
my-app/
├── infra/
│   └── api.ts
├── runtime/
│   ├── todos.fn.ts
│   └── utils.ts
├── notation-env.d.ts
├── notation.config.ts
├── package.json
└── tsconfig.json
```

## 2. Explore the code

The starter template gives you a project config, two directories – infrastructure and runtime – and a generated declarations file.

**`notation.config.ts`** – names the app and its entry file:

```ts [notation.config.ts]
import { defineConfig } from "@notation/core/config";

export default defineConfig({
  app: "my-app",
  entry: "infra/api.ts",
  defaultStage: "dev",
});
```

With this config, `npm run deploy` deploys `infra/api.ts` to the `dev` stage. To deploy to another stage, pass `--stage`: `npm run deploy -- --stage prod`. See [Project Config](./project-config.md).

**`infra/api.ts`** and **`runtime/todos.fn.ts`** – an API Gateway route, and the Lambda function that serves it:

::code-group

```ts [infra/api.ts]
import { api, router } from "@notation/aws/api-gateway";
import { getTodos } from "runtime/todos.fn" with { type: "runtime" };

const todoApi = api({ name: "todo-api" });
const todoRouter = router(todoApi);

todoRouter.get("/todos", getTodos);
```

```ts [runtime/todos.fn.ts]
import { json } from "@notation/aws/lambda.fn";
import { lambda } from "@notation/aws/lambda" with { type: "infra" };
import { api } from "./utils";

const { handle } = lambda({ id: "todos", timeout: 5, memory: 64 });

const todos = await api.get<any[]>("/todos");

export const getTodos = handle.apiRequest(() => {
  return json(todos);
});
```

::

Infrastructure and runtime live in the same codebase. `runtime/todos.fn.ts` is a runtime module, because `infra/api.ts` imports it `with { type: "runtime" }`. Its `lambda()` call declares one Lambda function with the ID `todos`, and `getTodos` runs in that function. The router wires `getTodos` to an API Gateway route, and Notation infers the intermediate resources – IAM roles, permissions, integrations, and so on. See [Runtime modules](./file-conventions.md#runtime-modules) and [Function Settings](./function-config.md).

`utils.ts` is an ordinary module. The `api.get("/todos")` call runs when the function starts, not when Notation builds infra.

**`notation-env.d.ts`** – generated by `notation types`. It types the imports that carry `type: "runtime"` or `type: "infra"`, so infra sees `getTodos` as a reference it can wire but not call. Notation commands write it again when the imports change. See [End-to-End Types](./types.md).

## 3. Visualize the graph

```sh
npm run viz
```

```sh
✔ Compiled infra/api.ts → 10 resources
→ https://notation.dev/viz/abc123
```

Opens a Mermaid chart of the resource graph. This is what Notation will deploy.

## 4. Deploy

```sh
npm run deploy
```

```sh
✔ Compiled infra/api.ts → 10 resources
✔ Diffed against state → 10 to create, 0 to update, 0 to destroy
✔ Deploying...

  ✔ iam-role/todos-role             created
  ✔ lambda/todos                    created
  ✔ api-gateway/todo-api            created
  ✔ integration/todo-api-todos      created
  ✔ route/GET /todos                created
  ...

✔ Deployed 10 resources

  GET https://abc123.execute-api.us-east-1.amazonaws.com/todos
```

Notation compiles your infrastructure, diffs it against the state of the `dev` stage, and deploys resources in dependency order. On first deploy, everything is created.

```sh
curl https://abc123.execute-api.us-east-1.amazonaws.com/todos
```

```json
[{ "userId": 1, "id": 1, "title": "delectus aut autem", "completed": false }, ...]
```

## 5. Make a change

Edit the handler in `runtime/todos.fn.ts`:

```ts [runtime/todos.fn.ts]
export const getTodos = handle.apiRequest(() => {
  return json(todos.filter((todo) => !todo.completed));
});
```

Then start watch mode:

```sh
npm run watch
```

```sh
✔ Watching infra/api.ts...
✔ runtime/todos.fn.ts changed
✔ Recompiled → 1 resource changed
✔ lambda/todos                    updated

  Ready.
```

Notation recompiles the graph and redeploys only the resources that changed.

## 6. Tear down

```sh
npm run destroy
```

```sh
✔ Compiled infra/api.ts → 10 resources
✔ Destroying in reverse dependency order...

  ✔ route/GET /todos                destroyed
  ✔ integration/todo-api-todos      destroyed
  ✔ api-gateway/todo-api            destroyed
  ✔ lambda/todos                    destroyed
  ✔ iam-role/todos-role             destroyed
  ...

✔ Destroyed 10 resources
```

Everything is removed in reverse dependency order.
